# 页面设计的执行入口

这是本库的原创实施规范，用于把一般 UI 设计原则落到项目中。书籍来源与阅读范围见 [来源说明](refactoring-ui-source.md)。下列步骤、示例和参数不是原书内容的逐章改写。

## 从用户任务建立页面

先确定用户在这一屏要完成的动作、作决定需要的信息和完成后的反馈。例如库存补货页先解决“哪些商品需要补货、补多少、提交后怎样确认”，再决定侧栏和卡片形状。已有项目沿用导航和组件契约；只有内容关系需要改变时才动布局。

用真实的长短文案和数据搭出一个可操作的纵向切片。先跑通读取、编辑、提交、反馈，再铺开其他区块，避免在未验证的页面骨架上精修装饰。数据不足时标明演示内容，不虚构业务事实。

## 确定气质与比较方案

把希望传达的气质落实到字体、色彩、圆角和界面用语，检查它们是否表达同一种态度；不要只凭“某行业应该是什么颜色”作决定。已有品牌、用户指定的参考和内容语境优先。

探索布局时可先用灰度或粗线框检验信息关系，确定后尽快进入实际界面。线框是决策工具，不必为了保留它而反复精修；明确要求忠实还原彩色参考时，不把灰度探索当成额外交付。

尺寸或色阶难选时，先比较当前档位与两侧有明显差别的候选，保留更适合真实内容的一项。避免逐像素试探；宽容器和大区块的档位可以更疏，紧凑控件的档位更细。

迭代顺序可以先完成较小的闭环，但不能据此删减用户明确要求的功能。不要在设计中暗示当前尚未实现的上传、导出或提交能力。

## 按缺陷选择材料

| 当前问题 | 读取材料 | 应产生的变化 |
|---|---|---|
| 看不出重点、主按钮不清楚、模块像一堵墙 | [层级与布局](ui-layout.md) | 明确阅读顺序、内容分组和操作优先级 |
| 页面松散或拥挤、小屏错位 | [层级与布局](ui-layout.md) | 调整容器、间距和响应式结构 |
| 字难读、颜色太杂、暗色主题不清楚 | [文字与颜色](ui-type-color.md) | 建立字体角色、颜色角色和状态对比 |
| 卡片层层套、阴影混乱、图片压字 | [层次与媒体](ui-depth-media.md) | 简化表面、稳定图片与文字关系 |
| 页面已完成，需要改版检查 | [设计验收](ui-review.md) | 提交可定位的问题、修改和验证结果 |
| 从零建立样式变量 | [CSS 起点](../templates/ui-foundation-tokens.css) | 在项目已有 token 上选择性补齐 |

## 与艺术风格、动效的关系

1. 先验证内容和操作是否清楚，再从 `data/index.json` 选风格或效果。静态界面的问题不能用入场动画遮住。
2. 有设计系统时，将本库的颜色、间距、圆角和阴影映射到现有语义 token，不并行建立第二套命名。
3. 用户指定的表现力可以保留；把艺术表达集中到标题、图像或重点区块，让表单、表格和阅读区维持可辨识的交互。
4. 无明确目的时不加持续动画。需要时，说明它用于反馈、引导还是叙事，并保留减少动画模式和静态可读性。
5. 演示模板只提供起点。中文、数据密集页面、触屏和深色模式需要分别评估，不能按整页比例缩放。

## 交付时给出可核查的理由

用“问题 → 修改 → 结果”解释关键决策。例如：“补货数量和商品描述混在一起；把数量列右对齐并提升字重，描述保留次级颜色；现在可逐行比较数量。”避免只说“更高级”。

记录最少但有用的设计约定：主要动作、内容宽度、字体角色、颜色角色、分组间距和效果预算。完成后按 [设计验收](ui-review.md) 检查实际页面；不能渲染时明确区分静态检查与视觉验证。
