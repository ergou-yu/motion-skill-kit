# 页面设计验收与持续改进

这是本库原创的验证流程。按实际修改范围选检查项，不将静态代码校验称作浏览器验证，也不把一次检查称作完整无障碍合规认证。

## 查什么、怎样取证

| 维度 | 验收问题 | 可观察证据 |
|---|---|---|
| 任务与层级 | 用户先看什么、下一步做什么？ | 主要内容与操作在真实页面中易辨认 |
| 分组与布局 | 帮助文字、字段、操作是否有明确归属？ | 宽屏与窄屏都能判断信息关系 |
| 文字与密度 | 长标题、长中文、数字和单位是否可读？ | 没有意外截断、拥挤或整页横向溢出 |
| 颜色 | 当前状态与主题中的前景/背景是否合格？ | 计算实际颜色配对，记录测量值 |
| 图片与表面 | 换一张图或上传异常比例后是否稳定？ | 主体保留、文字可读、失败有替代内容 |
| 组件状态 | 默认、悬停、聚焦、选中、禁用、错误是否一致？ | 鼠标与键盘操作均能理解状态 |
| 内容状态 | 加载、空、无结果、失败、成功是否有下一步？ | 提交或重试后可观察到反馈 |
| 动效 | 动画是否承担反馈或叙事目的？ | 减少动画时核心内容和操作仍完整 |

## 视口和输入方式

至少按目标项目的一窄一宽视口检查；可从 360px 与 1280px 试起，另检查 320 CSS px 下的重排。特定类型内容可能允许局部二维滚动，不应据此允许整个页面溢出。[W3C 重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

使用键盘走一遍本次涉及的操作，检查焦点可见、顺序合理、弹层能关闭且不遮住当前操作。触控目标可优先采用 44px 的产品设计起点；WCAG 2.2 AA 的 24×24 CSS px 要求还涉及间距与特定例外，两者不能混称为同一标准。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

对修改的文本检查放大后的换行。对本次引入的持续动画检查减少动画模式；对彩色状态检查移除颜色后是否仍能分辨。无需为纯文案或轻微样式变化建立庞大的测试套件。

涉及断点或复合组件时，增加一个中间宽度，检查组件宽度、文字归属和主要动作是否连续合理。合并表格呈现后验证独立排序、筛选和导出；调整字号后检查嵌套计算值；图片适配还要在最终展示尺寸下检查细节，不能只看原始大图。

## 原创评审示例：库存补货页

“数量列难比较”应对应到某个表格与状态，而非笼统评价“布局不高级”。修改可以是数值右对齐、统一数字格式、保留单位和行级错误；验收时填入 1 位与 5 位数量，并在窄屏检查表格区域滚动。

提交记录可以采用以下信息，不必固定输出一份长报告：

- 页面或组件、视口与状态；
- 观察到的问题及其对任务的影响；
- 实际修改和未解决的限制；
- 验证方式、结果，以及尚未运行的检查。

## 持续学习

收集参考界面时只记录一两个可检验的问题，例如“为什么这个筛选栏信息很多但仍好扫描”。在自有演示项目中复现信息关系、比较真实内容下的结果，再将有效经验写成适用条件明确的规则。不要复制品牌资产或把单个案例的装饰选择写成普遍铁律。

练习时可先凭观察复现一个小区域，再比较原图与实现的差异，每次只调整一种关系，例如行距、轮廓或表面层次。记录哪些内容与视口下有效，哪些情况下失效；开发工具可用于核查实现，但不要把抄到数值当成理解了设计原因。
