# 层次、媒体与细节的实施规则

这是本库的原创前端实施规范。优先维持内容可用，再决定装饰强度。

## 表面与空间

为层次分配用途：画布承载内容，表面组织相关信息，弹出层临时覆盖上下文。不同层次不需要全都使用阴影；留白、底色、局部边界和重叠也能表达关系。

同一界面的高光与阴影保持合理方向。可用一层较紧的接触阴影和一层较柔的环境阴影表达悬浮，但阴影大小不应按“看起来更精致”无上限增加。静态内容卡片、菜单和模态框的高度感应有区别；凹陷控件也需要清晰的文字与焦点。

使用双层阴影时，高处的表面不应仍带着同样浓重的贴地暗边。按压状态可减弱高度感，拖拽项可提高高度感；这些状态变化要对应真实交互，不能让静态卡片看起来都能拖动。平面风格可选择短的硬边投影或表面色差，不必统一增加模糊。

重叠图片、卡片或标题前，检查小屏的遮挡、点击区域、焦点可见性和滚动容器裁切。避免为修补遮挡不断提高 `z-index`；先检查定位和 stacking context。平面风格可以通过底色和分区保持层次，不必强行添加拟物阴影。

重叠头像等图像时，可用与当前表面同色的细窄间隔分开轮廓；主题或所在表面变化时也要更新它，不能固定成白边。

## 图片与真实内容

- 优先评估与业务有关的真实素材，再决定裁切和文字位置。图片的清晰度、光线和构图无法由大量动效弥补。
- 使用明确的比例容器、尺寸与适当的 `object-fit`；记录需要保留的主体位置。头像、产品图和文章封面可能需要不同裁切规则。
- 图片上的文字需要稳定对比，可使用有明确边界的文字底板或经过验证的遮罩。不能只在一张占位图上确认可读。
- 若照片同时有很亮和很暗的区域，先处理文字背后的图像复杂度：可调整裁切、降低图像对比或采用协调的单色处理，再验证文字。文字阴影只是辅助，不能代替稳定的前景与背景关系。
- 图标、标志和截图按各自用途处理：不要把小尺寸图标任意放大，也不要把需要阅读的界面截图缩到看不清。演示性的示意图需和真实可用的交互区分。
- 空间较大而图标只适合小尺寸时，可保留图标尺寸并用容器组织空间；很小的标志应准备简化版本。产品截图优先呈现关键区域或较紧凑的实际布局；只有用途确实是示意时才用简化界面，避免拿模糊微缩文字充当可读内容。
- 用户上传内容按极宽、极高、透明、纯白、纯黑和加载失败检查。提供稳定容器与失败替代内容；不要用 CSS 隐藏有意义的图文信息。
- 信息图片提供相应替代文本，纯装饰与可访问名称分离。装饰层不拦截操作，必要时 `pointer-events: none`。

上传图片与页面背景融在一起时，可在容器覆盖一层轻微内描边或内阴影，以保留图像轮廓；检查透明图和深浅背景。使用覆盖层时避免挡住点击，也不要误以为父容器的阴影一定会显示在子图片之上。

## 细节与状态

先调整现有元素的文字、图标、边界和状态，再考虑增加装饰。用局部强调色或背景纹理时，将强度限制在不会抢走阅读注意力的范围。大量边框使界面嘈杂时，先尝试分组和间距，不把所有边界一律删除。

空状态需区分“还没有内容”“搜索不到”“无权限”和“加载失败”，给出各自能执行的下一步。错误发生后应保留用户已输入的信息，并让重试结果可见。加载状态使用不会大幅改变后续布局的容器；持续效果仍遵守减少动画偏好。

首次使用尚无数据时，可收起暂时没有作用的筛选和表格装饰，突出创建或导入入口；筛选无结果时则保留当前条件与清除入口，不能套用同一个空模板。已有列表、引用、链接和选中状态可以承担品牌细节，不必另添装饰组件。

自定义单选卡片、上传区、开关或菜单时保留原生语义、键盘交互和清楚的选中反馈。视觉表现可以变化，交互契约仍需要让用户认得出来。
