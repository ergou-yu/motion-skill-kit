# 文字与颜色：建立角色，再选择样式

以下是本库的原创工程约定；与书籍相关的简明主题说明见 [来源说明](refactoring-ui-source.md)。

## 文字角色

按用途选少量角色：页标题、区块标题、正文、说明、数值和控件。先复用项目字体和字号，缺失时再建立尺度；不要逐个元素凭感觉累加字号。

- 选择字体时用真实中文、英文、数字、货币与标点试排，核对授权、字重文件、回退字体和加载后布局变化。展示标题的字体不必适合长正文。
- 字号 token 可用 `rem` 表达稳定的根字号关系；使用 `em` 时检查嵌套后的实际字号，避免连乘后悄悄偏离尺度。不要把字体家族的字重数量或流行程度当成质量硬门槛。[MDN 长度单位](https://developer.mozilla.org/en-US/docs/Web/CSS/length)
- 多字号同行优先观察文字基线；图标则按视觉中心微调。不要用统一垂直居中掩盖数字、单位与标签的关系。
- 行宽、字号与行高一起调。英文长文可从约 60ch 的行宽试起；`ch` 不等于汉字数，中文正文需按实际字宽另评估。长文行高可先试 1.6，短标题可先试 1.15，最终看字体与内容。
- 增大正文行宽时重新检查回行是否容易，必要时增大行高；缩小文字也可能需要更宽松的行距。大标题可用更紧的行距，但要检查中文、重音字符和回退字体是否碰撞或被裁切。
- 中文正文通常左对齐；长段落避免居中。数值列右对齐并按需要使用 `tabular-nums`，这样位数变化时仍易比较。
- 链接的表现取决于语境；正文链接要有可辨识的线索，不能只靠细微色差。导航中不必让每个链接都像主按钮。
- 字距按文字系统处理。英文展示标题可局部微调；中文、混排和短控件文字不要全站套用负字距。
- 英文全大写短标签可试着略增字距；不能用加字距把一款不适合小尺寸的展示字体强行变成正文字体。确需两端对齐的外文长文，结合正确的 `lang` 和 `hyphens: auto` 检查断词及空隙；中文另按自身排版规则处理。[MDN 断词说明](https://developer.mozilla.org/en-US/docs/Web/CSS/hyphens)

## 颜色角色

先分清画布、表面、主要文字、次级文字、边界、主要动作、聚焦与业务状态，再绑定具体颜色。语义变量让主题切换不必逐个替换组件中的色值。

为常用色准备够用的明暗档位，在真实按钮、提示和输入框上检查。调整颜色时同时观察色相、饱和度与明度；数值等距并不保证视觉等距。HSL 方便理解，项目也可使用已支持的其他色彩空间，不应把某种写法当成设计质量保证。

建立色阶时先确定实际可用的动作色、深色前景与浅色表面，再补齐缺少的中间档位；不要在各组件内临时生成大量近似颜色。浅色或深色端显得灰脏时，可小幅调整饱和度与色相后重新观察；HSL 的 `L` 不能直接当成对比度合格的证据。

低优先级状态标签若因白字而必须使用很深的底色，可以改试深色文字配浅色底，让状态清楚但不压过主要动作。调整后仍检查文字与背景的实际对比，并保留非颜色线索。

中性色可带少量冷暖倾向，但要与图片和品牌一致。彩色底上的辅助文字选择协调且可读的前景色，避免直接复用浅色主题中的灰字。用透明度调文字前应确认其与每种实际背景合成后的结果。

深色主题应重新分配表面、文字和状态颜色，并检查阴影是否仍能表达层次；不能只反转亮度。透明卡片、渐变、图片和混合模式还要检查背景变化后的最差情形。

## 可读与可辨认的约束

- 普通文字对比至少 4.5:1；符合“大文本”定义时至少 3:1。大文本指约 24 CSS px 常规字或 18.67 CSS px 粗体；不要向上取整对比结果来宣称通过。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 成功、警告、错误、选中和图表分类配合文字、形状或图案，不能仅用红绿等颜色区分。[W3C 颜色使用说明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- 灰度检查有助于发现层级问题，但不能代替对比计算、色觉差异检查或真实阅读测试。
- 本库的 [CSS 起点](../templates/ui-foundation-tokens.css) 用固定前景/背景配对方便复用；修改品牌色、主题或透明度后重新验证相关配对。
