# 层级与布局：先处理信息关系

本文件是本库自主制定的页面实施规则；数值示例是可调整的起点。

## 注意力如何分配

- 先标出核心内容、辅助说明和附属信息，再分配字号、字重、颜色与位置。次要信息仍需达到可读对比，不能靠近乎不可见的浅灰实现层级。
- 若每个标题、图标、数字和按钮都醒目，先降低不重要元素的视觉重量，再看是否需要增强重点。大而粗的图标往往比同列文字更抢眼。
- 同一决策区域让主要动作易辨认，次级动作保持可发现。危险操作需要可理解的文案与适当确认，不因视觉层级较低而失去危险含义。
- 在语境足够明确时精简重复的可见说明；表单的程序化名称、单位、错误关联和必要业务说明仍要保留。placeholder 不能承担唯一的标签职责。
- 判断用户在找“哪类信息”还是在比较“多少”：参数查询可让属性名成为扫描锚点，指标比较可让数值成为重点。数据与标签的视觉优先级由任务决定，不是固定的“大数字、小标签”模板。
- DOM 标题层级表达内容结构，CSS 表达视觉大小；不可为了变小把 `h2` 改成无语义的 `div`。布局改变后核对键盘顺序与阅读顺序。

## 分组与空间

先按任务关系建立组，再定义组内和组间距离。例如标签到输入框 8px、字段到下一字段 24px，可以表达归属；这不是固定公式，紧凑表格和长表单应按密度调整。

优先用容器 `gap` 和组件内边距表达关系。标题应更靠近它引出的内容；错误提示属于对应字段；页级操作与局部操作应有空间或位置区分。截图中如果无法判断一段帮助文字属于上方还是下方字段，说明分组尚未成立。

选择少量间距档位，必要时增加有理由的例外。整页的节奏来自重复关系，不来自所有组件使用相同 padding。数据操作页可更紧凑，叙事页面可有更大的停顿。

难判断留白是否足够时，先做一个明显宽松的版本，再收紧到信息关系清楚、扫描效率合适的位置；不要只以“刚好不挤”为终点。图标与计数、按钮与说明等横向组合也适用组内近、组间远的原则。

## 内容宽度与响应式

- 文本、表单、图表分别确定适合的宽度；宽屏可保留空白，也可把辅助说明放在侧列，无需把正文拉满。
- 登录框等有理想宽度的组件优先设置上限，空间不足时再收缩。不要因切换栅格占比，让可用空间更大的视口反而得到更窄的组件；修改断点后检查中间宽度。
- 栅格服务内容。固定宽度导航与弹性主区可以共存；用 `minmax(0, 1fr)`、子元素 `min-width: 0` 和合理换行处理长内容。
- 断点以内容开始拥挤的位置为依据。窄屏可改堆叠、切换摘要呈现或把工具栏分行，不能把桌面结构整体缩小。
- 字号、控件高度、内边距独立调节。大标题可以流动缩放，正文和触控目标保持可用；组件缩小时检查文字是否仍容纳真实内容。
- 表格优先保留比较关系。确需横向滚动时把滚动限制在表格区域，并让用户发现还有内容，不把整个页面做成横向画布。

## 组织复合信息

相关信息不一定各占一列。例如补货表的商品名和规格可在同一单元格内分出主次，给数量和操作留出空间；需要独立排序、筛选、导出或逐列比较的字段应保留相应能力。不能为了减少列数破坏表头关联和数据契约。

图标或分隔线过于抢眼时，比较“减轻颜色”与“调整线条重量”两种方案，不只扩大旁边的文字。装饰性边界可柔化；识别输入框、选中状态和焦点所必需的边界仍要保持足够辨识度。

## 实施示例

补货页可以采用“筛选工具栏 → 结果数量 → 商品与数量表格 → 提交反馈”的顺序。宽屏将帮助说明放旁边，窄屏移到相应输入附近；空结果显示清除筛选，首次使用显示导入商品。这是原创示例，不是某个通用版式的强制模板。
